# 🔍 Руководство по языку фильтрации Filter DSL

**Filter DSL** — это встроенный в **NullCA** высокопроизводительный язык запросов, который компилируется в синтаксическое дерево (AST) и фильтрует миллионы перехваченных пакетов в оперативной памяти без задержек.

В Cockpit строка фильтрации активируется нажатием клавиши `[/]`.

---

## 📌 Синтаксис и операторы

Язык поддерживает логические связки, группировку скобками и сравнение чисел и строк:

| Оператор | Название | Пример |
| :---: | :--- | :--- |
| `==` | Равенство | `proto == "http2"`, `status == 200` |
| `!=` | Неравенство | `method != "OPTIONS"`, `proto != "raw"` |
| `<` / `<=` | Меньше / Меньше или равно | `status < 400`, `len <= 512` |
| `>` / `>=` | Больше / Больше или равно | `status >= 500`, `size > 4096` |
| `contains` | Поиск подстроки (case-insensitive) | `body contains "token"`, `path contains "/admin"` |
| `&&` | Логическое И (And) | `proto == "ws" && len > 100` |
| `||` | Логическое ИЛИ (Or) | `status == 401 || status == 403` |
| `!` | Логическое НЕ (Not) | `!(proto == "redis")` |
| `( )` | Приоритет вычислений | `(status >= 400 || has_secret == true) && proto == "http1"` |

---

## 🏷️ Доступные поля

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `proto` / `protocol` | String | Протокол пакета: `"http1"`, `"http2"`, `"ws"`, `"grpc"`, `"x509"`, `"redis"`, `"sql"`, `"smtp"`, `"raw"` |
| `method` | String | HTTP-метод: `"GET"`, `"POST"`, `"PUT"`, `"DELETE"`, `"PATCH"` и т.д. |
| `path` / `uri` | String | Запрашиваемый URI-путь (например, `"/api/v1/auth"`) |
| `status` / `code` | Number | Числовой HTTP-код статуса ответа (например, `200`, `404`, `500`) |
| `dir` / `direction` | String | Направление пакета: `"in"` (Ingress / приём) или `"out"` (Egress / отправка) |
| `len` / `size` | Number | Размер расшифрованного пакета в байтах |
| `pid` | Number | Идентификатор процесса ОС, породившего или принявшего пакет |
| `comm` / `process` | String | Имя бинарника/процесса (например, `"curl"`, `"python3"`, `"node"`) |
| `fd` | Number | Номер файлового дескриптора сетевого сокета |
| `body` / `payload` | String | Сырое тело полезной нагрузки пакета |
| `contains` | Substring | Глобальный поиск подстроки по всей полезной нагрузке |
| `has_secret` | Boolean | Наличие обнаруженных токенов, JWT или CTF-флагов (`true` / `false`) |

---

## 💡 Практические примеры

### 1. Поиск флагов и уязвимостей в CTF Attack-Defense:
```text
contains "flag{" || contains "FLAG{" || has_secret == true
```

### 2. Отслеживание атак и серверных сбоев (5xx ошибки):
```text
status >= 500 && dir == "in"
```

### 3. Анализ микросервисных gRPC и Protobuf вызовов:
```text
proto == "grpc" && len > 64
```

### 4. Мониторинг WebSocket соединений:
```text
proto == "ws" && !(body contains "ping")
```

### 5. Выявление неавторизованного доступа (401 Unauthorized / 403 Forbidden):
```text
(status == 401 || status == 403) && method == "POST"
```

### 6. Фильтрация запросов конкретного процесса по имени:
```text
comm == "my_service" && method == "POST" && path contains "/webhook"
```

## 📜 История фильтров в Cockpit

В режиме ввода фильтра (`[/]`):
- Клавиша **`[Up]`**: подставляет предыдущее выражение из истории фильтров сессии.
- Клавиша **`[Down]`**: перемещается вперед по истории.
- Клавиша **`[Tab]`**: автоматически подставляет популярные шаблоны (`proto == "http2"`, `status >= 400` и др.).
- Клавиша **`[Enter]`**: применяет фильтр и сохраняет его в историю.
- Клавиша **`[Esc]`**: отменяет редактирование без изменения текущего фильтра.
- Пустой ввод и **`[Enter]`**: сбрасывает активный фильтр, отображая все пакеты.
